# スタンプ注文_保険代理店様向け（GAS注文フォーム）

プルデンシャル生命保険株式会社の営業社員様向けに、会社名・支店名・個人名・連絡先を彫刻した
住所印（自動スタンプ台内蔵）を注文いただけるWeb注文フォーム。
以下の2商品から選択できる（2026-09-04にサンスタンパーを追加。それまではシャイニーの単一商品）:

| 商品キー | 商品 | メーカー・型番 | サイズ |
|---|---|---|---|
| `shiny` | シャイニースタンプ | シャイニー製／Shiny Printer S-844 | 22mm×58mm |
| `sun` | サンスタンパー | サンビー製／A型 | 23mm×63mm |

「印鑑販売_行政書士様向け」（GitHub: `ria1107/hanko-order-form`）と同じ仕組み
（Square決済リンク発行・Notion自動記帳・Slack通知・お客様への自動確認メール）を流用して作った、
別商品の独立した仕組み。

## 構成（2026-08-30、GitHub Pages化のため独立リポジトリへ分離）

画面（`docs/index.html`）をGitHub Pagesで配信し、`GAS_プルデンシャル版_API/`は
doPostで注文データを受け取るAPI専用の役割のみを持つ。印鑑販売フォームの「_API」版と同じ構成。

| フォルダー | 用途 |
|---|---|
| `docs/` | GitHub Pagesで配信するフォーム画面（`index.html`） |
| `GAS_プルデンシャル版_API/` | 注文データを受け取るバックエンド（Google Apps Script） |
| `assets/` | 商品写真の元データ（`docs/index.html`にはbase64で埋め込み済みなので、配信には使わない） |

以前は画面もGASプロジェクト内に同居させていたが（`doGet`でHTML配信）、
GitHub Pagesで配信するために画面部分を`docs/`へ切り出した。
`docs/index.html`側の`API_URL`はGASのデプロイURLを直接書いているため、
再デプロイでURLが変わった場合は`docs/index.html`側も書き換える必要がある
（印鑑販売フォームの`doGet`が自動でURLを埋め込む方式とは異なる点に注意）。

### 公開範囲について

このフォームには実在の取引先企業名「プルデンシャル生命保険株式会社」がコードに含まれるが、
GitHub Pagesで画面を配信する都合上、**このリポジトリは公開リポジトリ**にしている
（西元さんに確認済み・2026-08-30）。GitHub Pagesはリポジトリの公開/非公開設定とは別に、
配信されるページ自体がインターネット上で誰でも閲覧できる仕組みのため、非公開リポジトリにしても
画面の内容（会社名を含む）は隠せない。もともとお客様に配るURLなので、この点は問題ない。

商品・価格は`GAS_プルデンシャル版_API/Code.js`冒頭の`const PRODUCTS = {...}`と

## フォーム入力項目

**商品選択**
- シャイニースタンプ／サンスタンパーの2択（ラジオボタン式の商品カード。デフォルトはシャイニー）
- 選択した商品は`productType`（`shiny`または`sun`）としてGASへ送信される。
  古いキャッシュの画面など`productType`が無い場合、GAS側はシャイニーとして扱う

**スタンプに彫刻する内容**
- 社名（初期値「プルデンシャル生命保険株式会社」を入力済み。編集可能）
- 支店名（必須）
- お名前（必須）
- 郵便番号（必須。ハイフンあり／なしどちらでも受付。サーバー側で`123-4567`形式に正規化）
- 住所（必須。郵便番号から住所を検索するボタンつき）
- 電話番号（必須）
- FAX番号（任意）
- 携帯電話番号（任意）
- メールアドレス（必須。注文確認メールの送信先）

**配送先**
- 「配送先は上記と同じ」チェックボックス（デフォルトON）
- チェックを外すと、配送先専用の郵便番号・住所・お届け先氏名・電話番号の入力欄が表示される（このときのみ必須）

## 送信後の処理

1. **Square決済リンクの自動発行**（`createSquarePaymentLink`。印鑑販売フォームと同一実装）
   - 明細：選択した商品の本体 4,950円／送料 440円
2. **お客様への自動確認メール**（`GmailApp.sendEmail`）
   - 入力されたメールアドレス宛に、彫刻内容・お届け先・合計金額・Square決済リンクを送信
   - `ADMIN_EMAIL`をbccに追加
3. **Slack通知**
   - `SLACK_WEBHOOK_URL`・`SLACK_MEMBER_ID`（スクリプトプロパティ）を使用
   - 誰が何を注文したか一目でわかる内容（注文者・会社/支店・合計金額・彫刻内容・お届け先）
4. **Notionへの自動記帳**（`recordOrderToNotion_`。印鑑販売フォームと同じ実装パターン）
   - DB_プロジェクトに案件ページを1件作成
     - 案件名：`{YYMMDD}_{お名前}_{商品名}`（商品名は`シャイニースタンプ`または`サンスタンパー`）
     - 開始日：注文日／担当者：杉角賢太郎／進捗状況：`完了(クレジット)`
   - DB_現金出納帳_F3に、商品行と送料の行を1行ずつ作成し、DB_プロジェクトのページとリレーション
     - 商品行：品目`シャイニースタンプ(プルデンシャル生命保険様)`または
       `サンスタンパー(プルデンシャル生命保険様)`／数量1／項目`売上`／種別`印鑑`／
       単価(税抜) 4,950÷1.1=4,500／課税対象`はい(10%)`
     - 送料の行も同様に税抜換算して記録
   - 案件ページ作成直後はNotion側のインデックスが追いつかずリレーションが空になることがあるため、
     1.5秒待ってから明細行を作成している（2026-08-27の実機テストで判明・修正済み）
   - Notion書き込みが失敗しても、メール送信・Slack通知・Square決済など他の処理には影響しない
     （`try/catch`で囲み、エラーはログに残すのみ）
5. **スプレッドシートへの記帳**
   - このフォーム専用のシート（`注文台帳_スタンプ_プルデンシャル`）に1行追記
   - 印鑑注文の台帳とは別シートなので混在しない。無ければヘッダー行つきで自動作成される
   - 2026-09-04に末尾へ「商品」列を追加。既存シートのヘッダーが古い（列が足りない）場合は
     次の注文時に1行目が自動で書き直される

## スクリプトのプロパティ（設定済み・2026-08-27〜28に西元さんが設定）

Apps Scriptエディタ → 歯車アイコン「プロジェクトの設定」→ 一番下の「スクリプト プロパティ」に、
以下を登録する。**コードには一切直書きしない**。

| プロパティ名 | 内容 |
|---|---|
| `ADMIN_EMAIL` | 通知・BCC先の管理者メールアドレス |
| `SLACK_WEBHOOK_URL` | Slack Incoming WebhookのURL |
| `SLACK_MEMBER_ID` | Slackでメンションする担当者のメンバーID |
| `SPREADSHEET_ID` | 注文台帳スプレッドシートのID（`setupCreateOrderSpreadsheet`関数の実行で自動設定済み） |
| `SQUARE_ACCESS_TOKEN` | Square APIのアクセストークン |
| `SQUARE_LOCATION_ID` | SquareのLocation ID |
| `SQUARE_API_BASE` | `https://connect.squareupsandbox.com`（テスト）または`https://connect.squareup.com`（本番） |
| `NOTION_API_KEY` | Notion連携用インテグレーションのシークレット |

※印鑑販売フォームにある`PRINTER_EMAIL`（フリーメイト印刷業者への発注ドラフト用）は、
このフォームでは使わないので設定不要。
